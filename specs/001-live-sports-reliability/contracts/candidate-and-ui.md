# Candidate, catalogue, player and hero contracts

Status: proposed contract for GPT Work review. No deployed API changes.

## Candidate request and response
Retain the existing route and legacy input compatibility. Add contractVersion=2, eventId, scheduledStartUtc, scheduledEndUtc (nullable), sportId, competitionId, division (nullable), homeId/awayId (nullable), participant names/aliases, status/statusObservedAtUtc, and broadcaster entries carrying service/network identity, market, source and observedAtUtc. All timestamps are ISO-8601 UTC; a UI timezone is display context, never a substitute for an instant. No provider credentials or playback URLs in this API.

Validate bounded input: names/title <=256 characters each; at most 16 broadcasters and 16 aliases per participant; limit <=12 per page, stable opaque cursor scoped to event/version. Invalid time ranges or IDs =>400; unsupported contract version => explicit error. Legacy requests missing identity/time may return plausible/unverified candidates only, never verified. Do not assume a public legacy endpoint has authorization merely because it works; preserve existing connectivity while separately reviewing access/rate limits.

Response carries contractVersion, eventId, generatedAtUtc, catalogueRevision/importCompletedAtUtc, evidenceAsOfUtc, expiresAtUtc, candidates, nextCursor and totalEligible. Each candidate: sourceId, providerItemId (opaque string), logicalServiceId, variantIds, displayName, serviceMarket, tier (verified/plausible/unverified), evidence[] (type/source/observedAt/programme interval/fixture identity/reason), rejection/contradiction reasons where operator-visible, playbackObservation (unknown/pass/fail plus checkedAt, distinct from tier). No credential-bearing source URLs. The client validates version, event identity, expiry and evidence before displaying a tier. Legacy definite/likely/maybe values never map directly to verified UI state.

## Decision rules, in order
1. Apply source-scoped AU ESPN 1 exclusion before candidate scoring and before UI display. Suppress absent inventory, explicit inactive/placeholder/replay/highlight/expired feeds. Preserve backend records. A catalogue item is not a logical service across all providers.
2. Hard contradictions (different fixture/division/competition, explicit non-overlapping programme, confirmed content-guide mismatch) disqualify fixture recommendations. Keep operator audit reasons. A missing guide is not a contradiction but cannot establish verification.
3. Verified: unambiguous fixture identity (or both scoped participant identities plus competition/division) AND time-overlapping fixture-specific programme/event-feed evidence AND no contradictions AND trustworthy regional service identity. Name-only team matches do not qualify. Programme overlap requires a strictly positive interval intersection with the fixture interval; touching endpoints are not overlap. For a named event feed with a declared fixture start, absolute difference from fixture kickoff must be <=15 minutes (exactly15 passes,15 minutes+1ms fails), even when the two-hour intervals still overlap. Programme-only evidence may include pregame coverage; its programme start is not assumed to be kickoff, so it requires exact fixture identity and positive overlap rather than a kickoff-delta test. A guide alone cannot establish which fixture a generic sports programme contains. A declared schedule tolerance cannot turn a disjoint programme into verified evidence. Use explicit event end when known; absent end requires source-specific duration policy, recorded as inferred. Inferred end alone cannot resolve conflicting evidence.
4. Plausible: current, sourced competition/fixture broadcast assignment for that regional service, valid for scheduled time, but no fixture-specific programme confirmation. Broad network affinity is insufficient. No arbitrary static broadcaster-rights table can masquerade as current evidence.
5. Unverified: generic network/league affinity, missing region/time/identity, stale evidence or unsupported legacy confidence. Never mix into initial recommendations; show explanatory labels under Find other channels. Unrelated named fixtures are excluded rather than shown here.
6. Sort by tier, then evidence specificity/freshness, then observed playback health, then market/language preference, then measured quality, then logicalServiceId. Claimed HD/4K labels do not establish measured quality. A playback failure can demote/suppress a variant, never move generic evidence above verified evidence. Preserve healthy backups separately.
7. Collapse established service variants, not independent services. Initial selection takes six verified services when available; plausible fills only remaining slots. Within the same evidence tier, reserve a place for an eligible alternate regional broadcaster if otherwise one network would occupy all slots. Never displace verified with plausible to enforce variety. Remaining verified entries stay reachable in alternatives. Stable IDs break ties.

Programme evidence refresh: <=5 minutes for current live verification; event-specific schedule evidence for future fixtures must be fetched within 24 hours, displayed as scheduled rather than live. Verified live candidate expires at earliest programme end, fixture end, explicit status termination or evidence timestamp+5 minutes. Conflicting or unavailable refresh downgrades honestly; do not keep a false verified label. Catalogue snapshot older than 24 hours triggers stale notice and requires fresh availability confirmation before live assertions. Cached results bind to event/version/catalogue revision and expire; cancellation invalidates them.

Playback observation means a separately authorized sample at a stated time. Even a verified fixture channel must not be called currently playing successfully without that observation. A future scheduled match is never Watch Live.

## Soccer and exclusion policy
Soccer selection reads current present live inventory plus categories dynamically, with source-scoped reviewed continuous-service identities and event evidence rules. Categories and names are discovery inputs, not admission proof. Continuous mixed-sport services require documented soccer carriage to enter the curated list; a network keyword alone cannot admit all channels. Temporary feeds qualify only during their confirmed soccer programme window (including a 30-minute pre-event entry window), then expire automatically.

Persist logical IDs and variant linkage; don't rewrite provider IDs, EPG IDs or saved references during dedupe. Source-scoped AU ESPN 1 identity list includes discovered variants and structured exact aliases; avoid substring matching ESPN 1 against ESPN 10/11 or ESPN 2. Newly unknown ESPN identities require classification; they cannot bypass a known excluded identity via a rename. Apply policy to fresh/cached backend data, local fallback, list/count/search, saved/last channel, direct tune and hero selection. Admin audit remains read-only accessible under existing controls. Do not delete inventory or saved records.

## Player observability and stale-frame state
One monotonically increasing tuneGeneration owns every resolution, callback and frame. Trace milestones using a monotonic clock: intent, UI loading visible, debounce scheduled/fired/cancelled, source resolution start/end, previous-source close, new-source open, prepare start/end, BUFFERING/READY, first rendered video frame, first audio, overlay cleared, error/retry, background/foreground and engine swap. Include engine/version, stream type, anonymized source/service ID and network profile; omit URLs/tokens and personal data. Segment delays; missing milestone is unknown, never zero. Retain bounded diagnostic records under existing QA controls, propose seven-day maximum QA retention; no new production telemetry pipeline in scope.

Keep existing 1500ms isolated threshold and 500ms rapid debounce as baseline. Test real input cancellation, not just the delay function. An isolated tune may open once, rapid hold may open first and final only, never intermediate selections. Retries are bounded and count toward provider opens; no speculative candidate probes, parallel fallback race, or decoder prewarming that opens extra provider sessions. A failed first/final tune cannot silently authorize more retries than baseline.

Display selected-channel loading within 100ms. Old frames must be cleared or explicitly labelled previous content; freezeFrame across mpv/Exo transitions is owned by the old generation until replaced/hidden. First-frame callback clears the transition only for its current generation. Handle cancellation, failure, timeout and view disposal. Do not infer visual freshness from READY alone.

## Hero lifecycle
Use existing headline eligibility and stable event IDs. Candidate window for PRE is [now, now+168h); IN requires status observed within five minutes and a non-expired event interval. If live interval is missing, require refreshed source IN status and revalidate every minute; stale IN disappears from live priority/badge until refreshed. Source outages show a last-updated state and safe upcoming entries, not indefinitely live items.

Partition fresh live before upcoming, then editorial priority and start time with stable ID tie-break. Apply sport/competition variety within each partition. Keep maximum twelve and existing ten-second rotation; pause rotation during direct interaction as current behavior requires. Preserve selected key across refresh, choose next eligible key if removed, never silently retarget an in-progress click by index. Refresh on entry/resume and every 60 seconds visible with single-flight/coalescing; tick expiry every 60 seconds even if network emits nothing. Cancel work off-screen. Backoff source errors without opening streams. Zero eligible events uses intentional empty/fallback treatment.

Default action remains View event. Watch Live requires current live status plus non-expired verified fixture evidence and a usable non-excluded target, revalidated on click. This overhaul need not add Watch Live. Badge LIVE describes a fresh fixture status, not confirmed stream availability.
